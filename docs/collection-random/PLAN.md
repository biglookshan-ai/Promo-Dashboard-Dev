# Collection 区间随机排序

2026-11-23 用户新增需求：保留既有固定排序，可让第 16 至 40 位随机；也可将置顶区间随机。

## 行为

- 在 Collection 默认设置中配置一或多个互不重叠的区间（含起止位置），例如 `16–40` 或 `1–15`、`16–40`。
- 先按当前排序计划与 Collection 默认设置确定基础顺序，再仅对区间里的产品洗牌；区间外和其他区间的产品不相互交换。
- 每次页面打开/刷新生成新种子；同一次浏览中的筛选、翻页、加载更多、改回默认排序复用种子。切换至另一个系列 Collection 时重新生成。
- 筛选从完整基础顺序的随机结果中取子集，避免外面的产品因筛选补进随机池。位置以筛选前的默认列表为准。
- 用户主动选择 Sort by 时尊重其选择；促销链接有自己的固定位置或排序时也尊重其独立配置。没有自定义的促销链接沿用 Collection 随机规则。
- 不写后台随机顺序。现有后台同步、快照、冲突处理和计划到期还原仍以固定基础顺序运作。计划暂停后，Collection 本身配置的随机区间仍在默认列表上生效。
- 配置独立于计划，计划生效时也适用；因此设置 `1–15` 可打乱计划置顶产品。保存区间后无需等待计划开始/结束。
- 空区间列表关闭随机；产品少于结束位置时截到最后一个，少于两个产品时原样；完全超出数量的区间不执行。
- 最多 20 段，位置为 1–1000（当前前台引擎最多取 20×50 个产品），禁止重叠、倒置和非整数。

## 代码和数据

Collection metafield `custom.cgp_random_ranges`，类型 `json`，值为 `[{"start":16,"end":40}]`。复用 `/api/schedule/col-sort`、页面能上线权限与 `pins.defsort` 敏感功能，服务端统一校验后写入。未带新字段的旧调用保留原配置；复制另一个 Collection 的基础顺序不自动替换目标的随机区间。

`src/col-sort.js` 校验/描述；`src/col-sort-shop.js` 读写；`public/schedule.js` 共用设置面板；`src/col-status.js` 显示随机规则。主题从 head 初始注入与 collection.cgp-json 的 `randomRanges` 获取，客户端在完整列表排序后、分页前执行带页面种子的 Fisher–Yates。

主题三个文件同时维护 Search Panel 的 `theme-module` 副本，避免以后“写入主题”覆盖本功能。无需新增 app 权限或 Collection 产品写操作；仅增加一个 Collection 元字段，仍需配套发布 app 与主题代码才在正式店生效。
