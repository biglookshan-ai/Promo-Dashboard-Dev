## 📌 用户的 6 个需求

1. **计划太多不好找**:几十上百个计划,只靠标题看属于哪个活动。要能**按活动 / 品牌分组**,最好能智能分组或有筛选器。
2. **只选有货的产品**:清货时只给有库存的打折。可选「全部产品 / 有库存的」,默认按 **UK 仓**。
3. **产品表加一列 UK 库存**(Available 可售数)。
4. **组可以起名字**:现在只有「第 1 组、第 2 组」,看不出每组是什么。
5. **一个计划里多段时间 / 多种价格**:比如周一到周五一个价、周末另一个价,下周一回到前一个价或者回到原价。现在只能「复制成下一天」,一个计划只有一段时间。
6. **每个产品的改价记录**:改过几次价、分别在哪个计划,能追溯。

## 1️⃣ 计划列表:分组 + 筛选

**列表上方一排工具**:
- **分组方式**:按活动(默认)/ 按品牌 / 按开始月份 / 不分组
- **筛选**:活动、品牌(都能多选)+ 现有的状态页签(未结束 / 进行中 / 已排期 …)
- **搜索框**:搜计划名,**也能搜产品名 / SKU** → 列出包含这个产品的所有计划(包括已结束的)

**分组的样子**:
```
▾ Black Friday 2026          9 个计划 · 7 进行中 · 2 已排期
    Black Firday                       进行中  10 个产品
    Black Firday-Cindiskpro            进行中   6 个产品
    …
▾ 没关联活动                  3 个计划
    Leaplight 清货                      已排期  41 个产品
▸ Autumn Sale(已结束,收起)   5 个计划
```
- 每组可以收起 / 展开,记住你的选择;已经全部结束的组默认收起。
- **按品牌分**:品牌从计划里的产品自动算(不用手填)。一个计划有几个品牌时,放在**产品最多的那个品牌**下,行上标「+ 2 个品牌」;按品牌**筛选**时只要包含就算。
- 计划行上把「关联活动」显示清楚;可以**勾选几个计划 → 一起关联到某个活动**(老计划补关联很快)。

> 问题 ①:除了「关联活动」和自动按品牌,要不要再加一个**自己填的分组名**(比如「清货」「日常调价」)?我建议先不加,看用起来够不够。

## 2️⃣ 3️⃣ 库存:只选有货的 + 显示 UK 可售

**数据从哪来**:Shopify 里每个仓库的库存(这是唯一真源)。**UK 仓 = Shopify 里伦敦那个仓库**(你说的 Cinegearpro 仓)。
读的是 **Available(可售)**,不是 On hand。EW 是虚拟仓,不算。
- 「改价设置」里可以选哪个仓库算 UK 仓(默认自动认 Cinegearpro / 伦敦那个)。
- 库存单独小批量读(和款式图一样,不塞进读产品的大查询,怕超出单次查询上限);2 分钟内不重复读。
- ⚠️ 列出仓库名可能要多一个「读取仓库」权限(read_locations),做的时候先查;要加的话需要你在 Shopify 里同意一下。

**筛选**(在「改哪些产品」里,条件下面):
```
库存  ( 全部选项 )  ( 只要 UK 仓有货的 )
```
- **按选项算**:同一个产品,有货的颜色 / 卡口才打折,没货的选项不进清单。整个产品都没货就不出现。
- 对 Collection / 品牌标签 / 全店三种方式都能用;「指定产品」是自己点选的,不自动去掉,但会显示库存,另给一个「去掉没货的 N 个选项」按钮。
- 被筛掉的不算「排除」,换回「全部选项」就回来。

**产品表加一列「UK 可售」**:显示数字;0 是灰色,负数(超卖)标红;可以按它排序。

**注意:筛选是在编辑时按当时的库存算的**,保存后清单就固定了。
- 活动进行中卖完的:**继续保持折扣价**(默认;比如还能从别的仓发货 / 预订)
- 新到货的产品:不会自动加进来,要打开计划点「重新读」再保存

> 问题 ②:进行中卖完的,要不要有一个选项「UK 仓卖完就自动回到原价」?(要定时读库存,会稍微增加一点和 Shopify 的往来,做得到,但我建议先不做)

## 4️⃣ 组可以起名字

- 组标题变成「**① 工作日价 · 品牌 Leaplight · 降 20%**」,点名字直接改。
- 不填就自动用条件起名(比如「品牌 Leaplight」),和现在的说明一样。
- 名字也会显示在产品表的「哪一组」、计划列表、改价记录里。
- 最小的一项,半天以内。

## 5️⃣ 一个计划里多段时间 / 多种价格

### 用起来的样子
「什么时候」一段变成三选一:
```
( 一段时间 )  ( 几段时间 )  ( 每周重复 )
```
- **一段时间**:和现在一样。
- **几段时间**:一行一段,每段选开始、结束、用哪个价格。比如:
  ```
  11/24 00:00 → 11/28 23:59   价格 A(早鸟 15%)
  11/29 00:00 → 12/01 23:59   价格 B(黑五 25%)
  12/02 00:00 → 12/04 23:59   价格 A
  ```
- **每周重复**:选「从哪天到哪天」,再选每周哪几天用哪个价格。比如:
  ```
  11/3 → 11/30
  周一 – 周五   价格 A(降 10%)
  周六 – 周日   价格 B(降 20%)
  ```
  没安排到的时间(比如只设了周末)= **回到改价前**。

**价格 A / B**:
- 默认只有一个价格(和现在一样)。打开「不同时段用不同价格」后多一个价格 B(可以起名,比如「周末价」)。
- 产品**还是同一批**(同样的组和条件),只是每一组可以给 A、B 各设一个折扣 / 划线价;逐个填价的,产品表里 A、B 各一列。
- 时间表下面画一条**日历条**:每天是哪个价格(A 蓝 / B 橙 / 原价灰)一眼看清,鼠标停上去显示具体时间。

### 执行
- 存的时候按时间表**展开成一段一段**(最多 60 段 ≈ 30 周的工作日 + 周末),交给现在的执行器。
- 执行器本来就会:到了一段就换成这一段的价;两段连着(周五 23:59 → 周六 00:00)直接换价、不会先回原价;两段中间有空 → 自动回到改价前。每分钟检查一次,所以切换最多晚 1 分钟。
- 时间都按**店铺时区(伦敦)**,夏令时切换自动处理。
- 倒计时显示**当前这一段**的结束时间(比如周末价显示「还剩 1 天 4 小时」)。
- 「加进 Collection」「加减标签」跟着价格走:在打折的时段里加进去,回到原价的时段拿掉(和现在一样);A、B 连着时一直在。
- 两个计划改到同一产品、时间重叠的提醒,按每一段算。
- 已经开始的计划:过去的段不能改,以后的段可以改。
- 「跟随活动时间」:时间表自动裁到活动的开始和结束之间。
- 计划状态:在两段中间时显示「进行中 · 现在是原价,下一段 11/8 周六 00:00 开始」。

### 分两步做
- **5a. 几段时间 / 每周重复,同一个价格**(比如「只有周末打折」):改动小一些,先做。
- **5b. 不同时段不同价格**(A / B):在 5a 的基础上加价格版本。

> 问题 ③:「周一到周五 A、周末 B」和「只有周末打折、平时原价」哪个更常用?决定 5a、5b 谁先上。

## 6️⃣ 产品的改价记录

**从哪里打开**:编辑页产品表每行一个「记录」小图标;「受管产品」「价格账本」里点产品名也能打开。

**内容**:
```
Leaplight Heavy Duty C Clamp · LYM4
被 app 改过 6 次价 · 在 4 个计划里 · 现在:「Mobile&Action Black Friday」接管中(£18.40)

改价记录
  11/02 07:17  £23.00 → £18.40(划线 £23.00)  Mobile&Action Black Friday · 开始
  10/27 00:00  £20.70 → £23.00               Autumn Sale · 结束,回到改价前
  10/20 08:00  £23.00 → £20.70               Autumn Sale · 开始
  10/18 14:02  ⚠ 发现有人在后台手改成 £22.00,暂停接管(Autumn Sale)
  …

包含这个产品的计划
  进行中  Mobile&Action Black Friday   11/2 → 12/4   £18.40
  已结束  Autumn Sale                   10/20 → 10/27  £20.70
  已排期  Leaplight 清货                12/5 →         £16.10
```
- 记录按**选项**分;一个产品多个选项时可以切换,也能看「全部选项」。
- 「价格账本」页加一个「按产品看」的方式(现在是按时间一条条)。

**技术上要顺手做的**:账本现在存在改价的主数据文件里(最多 5 万条),执行器每分钟都要读写整个文件,越积越大会拖慢。
改成单独一个只追加的文件(和「操作记录」一样),**不再限 5 万条**,老记录原样搬过去。

**限制要说明白**:
- 记的是 **app 改的价**,以及 app 接管期间发现的手动改价;
- 不在任何计划里时有人直接在 Shopify 后台改价,**记不到**(Shopify 没有价格历史的接口)。以后要的话,可以让 Shopify 每次改产品时通知 app 来补记。
