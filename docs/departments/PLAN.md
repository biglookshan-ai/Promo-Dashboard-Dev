# 部门负责人(2026-11-10 用户提出,方案已定)

> 用户:增加「部门负责人」——可以指定员工作为某个部门的负责人,他能设置对应页面里员工的权限、通知设置、能操作哪些功能。
> 用户定的 4 点(都选了推荐):① 每个页面 4 档 + 少数敏感功能单独勾;② 「能编辑」的员工保存 = 提交给负责人批准;
> ③ 负责人能把「待分配」的新同事拉进自己部门、也能移出;④ 负责人管本部门谁收哪些通知、发哪个部门群、什么时候(样式内容仍由管理员在消息中心统一)。

## 数据层级

```
店铺
├─ 管理员 ─────────── 什么都能做(和现在一样;Railway LARK_ADMIN_IDS / 第一个登录的)
├─ 部门 = 原来的「角色」升级(state.roles,key 不变:ops / pricing / design / copy …)
│   ├─ name
│   ├─ leads: [成员 id]                    ← 管理员指定,可以几个
│   ├─ ceiling: { 页面: 0–3 }              ← 管理员定的上限(老数据 = pages 里的页面都是 3)
│   ├─ capsOff: [敏感功能]                  ← 管理员给整个部门关掉的敏感功能
│   ├─ grants: { 成员 id: { levels: { 页面: 0–3 }, capsOff: [敏感功能] } }  ← 负责人在上限内给;没写 = 和上限一样
│   └─ notify: { 通知 key: { … } }         ← 第 4 期:本部门的人收哪些、发哪个部门群、什么时候
├─ 成员 members[](飞书登录的人)
│   ├─ roles: [部门 key](+ 'admin')       ← 属于哪些部门,可以几个(字段名不变)
│   └─ notifyMute: [通知]                  ← 我的通知(和现在一样)
└─ 消息中心 notifyCenter(管理员)          ← 样式、内容、全公司规则(管理员 / 公司群)
```

一句话:**管理员定天花板,负责人在天花板内给每个员工分,员工在分到的范围内干活。**

## 档位(每个页面一档)

| 档 | 叫法 | 能做什么 |
|---|---|---|
| 0 | 不能看 | 导航里没有这一页,服务器也拦 |
| 1 | 只看 | 能看、能复制链接;不能新建 / 修改 |
| 2 | 能编辑 | 新建、修改、存草稿;保存 = **提交给负责人批准**(批准前线上不变) |
| 3 | 能上线 | 发布 / 保存直接生效、暂停、结束、删除、调顺序、批准别人的修改 |

- 一个人在某页的档位 = 他所在各部门里 `min(部门上限, 负责人给的)` 取最高;负责人自己 = 本部门上限;管理员 = 全部 3。
- 设置、工具只给管理员(和现在一样)。「操作记录」所有登录的人都能看(不算页面权限)。
- **敏感功能**(默认跟着「能上线」,负责人 / 管理员可以单独关掉):
  - 改价:`price.control` 暂停 / 继续 / 提前结束;`price.hold` 处理被接管的产品;`price.export` 导出还原表
  - Collection 排序:`pins.defsort` 改 Collection 默认设置(含照另一个 Collection 排);`pins.rollback` 回滚顺序
  (清单在 `src/members.js` 的 `CAPS`,新加敏感功能在那里登记 + 服务器接口里 `needCap`)

## 谁能做什么

| | 管理员 | 部门负责人 | 员工 |
|---|---|---|---|
| 建 / 改 / 删部门、定上限、指定负责人 | ✅ | — | — |
| 给本部门员工定档位、关敏感功能 | ✅ | ✅(不超过上限,不能动别的负责人) | — |
| 把待分配的新同事拉进本部门 / 移出本部门 | ✅ | ✅(不能停用、不能给管理员) | — |
| 批准本部门「能编辑」员工的修改 | ✅ | ✅(那一页他得是「能上线」) | — |
| 本部门的通知(谁收、部门群、时间) | ✅ | ✅(第 4 期) | — |
| 消息中心(样式内容、全公司规则)、设置、工具 | ✅ | — | — |
| 我的通知 | ✅ | ✅ | ✅ |

所有权限改动记操作记录(谁、给谁、改了什么)。

## 审批怎么接

- 审批流程本来就有(提交 → 待审核 → 批准 / 退回,`schedule-actions` / `price-actions`),现在整体关着(`APPROVALS=on` 才开,开了 = 所有非管理员都要审批)。
- 新的:**按人按页面**——某人在某页是「能编辑」(2),他在这一页的保存就走提交;「能上线」(3)照旧直接生效。
  `actorOf(m)` 带上每页档位 `levels`,`schedule-actions` 的 `canApprove` / `isApprover` 按这条内容属于哪一页看档位;改价按 `price` 那一页。
- 批准人 = 提交人所在部门里那一页「能上线」的负责人(没有就管理员);能上线的同事也能批(反正他本来就能直接发)。
- 只要有人是「能编辑」档,「审核」页 / 待审核状态 / 提交审核的通知就对相关的人出现(`reviewsOn`);没人是这一档时界面和现在一样。

## 分期

1. **数据 + 服务器检查**(看不出变化):角色自动变部门(上限 = 原来的页面,都是能上线),所有人照旧;服务器按档位检查(只看的不能改、敏感功能)。
2. **管理员界面**:设置 → 成员与部门(部门名、负责人、每页上限、敏感功能、成员在哪些部门)。
3. **负责人界面**:左边导航「我的部门」(本部门员工 × 每页档位 + 敏感功能;拉待分配的进来 / 移出)。
4. **审批接上**:能编辑档的保存 = 提交,负责人在「审核」页批;通知「有内容等审批」发给负责人。
5. **部门通知**:负责人设本部门的人收哪些、部门群、什么时候;和消息中心的规则合起来去重;消息中心的「同部门」改按真的部门成员算。
